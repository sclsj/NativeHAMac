## Executable semantic reference

Run `node tools/climate-reference/semantic-oracle.mjs --check` to reproduce and compare the tracked `Tests/Fixtures/Climate/expected-semantics.json`. Run with `--print` to inspect new output without overwriting the expected file. `HA_REFERENCE_ROOT` can select a different read-only reference checkout. The checked fixture was generated and verified on 2026-09-13 using Node 22.23.1 and the reference's installed TypeScript 6.0.3.

The oracle parses the actual TypeScript with its AST, selects named top-level declarations and undecorated methods/getters, and transpiles their exact source text. It asserts that every requested declaration occurs exactly once and rejects unexpected decorators. It evaluates actual `clamp`, `supportsFeature`, climate constants/order, circular-slider coordinate/value/step/bounds/dual-thumb/keyboard methods, and temperature target/step/capability/button/event/payload methods. It does not reimplement the formulas under test. The complete relevant files were read before selection; each file's SHA-256, the reference revision, TypeScript version, and extracted member names are in the expected fixture. Missing dependencies or changed source/output fail the check rather than silently updating the expected output.

The harness supplies fixture object fields, a 320×320 bounding rectangle, a no-op key `preventDefault`, and recording event/API boundaries. It records calls to the temperature control's debounce boundary, then explicitly invokes the real payload method; it does not emulate or claim to measure the omitted debounce timer. The Fahrenheit unit binding is the established `°F` primitive. Imported icon constants use the reference's installed `@mdi/js`; no icon rendering is tested. No browser, DOM renderer, network, Hammer recognizer, Lit lifecycle, or native app code runs. This is semantic source evaluation, not a workaround for unavailable browser capture.

Results worth preserving in native conformance tests:

- Exact bottom/dead-zone center maps to minimum; points immediately on either side split to minimum/maximum. The center of the circle itself produces a mathematical value, but these pure mapping calls do not prove that the center is an interactive hit region.
- Pointer rounding uses zero-anchored steps after bounds. Negative half ties round toward positive infinity. Off-grid bounds can therefore produce a stepped result outside a bound; a paired low/high pointer can similarly round past an off-grid neighbor. These are observed reference outputs, not blanket approval of malformed native inputs.
- Temperature plus/minus adds the step and clamps without snapping to the pointer grid. A target of 22.25 with a +0.5 button becomes 22.75. Range button changes clamp against the other endpoint and send both endpoints.
- Arrow keys add/subtract a step without snapping; page keys use their actual stepped ten-percent path. The fixture preserves the changing/clear-changing/changed event sequence and floating-point values.
- Missing or zero temperature step falls back to 0.5°C or 1°F at the temperature-control getter. The raw circular-slider zero-step method itself produces NaN. Negative step is retained by the reference getter. These adversarial observations distinguish direct helper behavior from normal reachable control inputs.
- Feature masks and non-null targets independently gate single/range capabilities. A zero target is valid. Both capability getters can be true; the fixture does not assert simultaneous rendered controls because the actual rendering branch prioritizes single target.
- A changing event updates target state without a service call; a changed event calls `climate.set_temperature`, carrying one target for single mode or both endpoints for a range.

Special JSON values use explicit `{"$undefined":true}` and `{"$number":"NaN"}`/`"-0"` representations so JSON serialization cannot silently convert absence or non-finite results into null. Native tests should compare ordinary floating values with suitable numeric tolerance, keep adversarial cases explicit, and test their own disabled/read-only boundary separately. Passing `--check` proves reproducibility of these source-derived examples, not native correctness or visual parity.
