The correction compiles out the storage implementation, policy access, setup/shutdown, diagnostic request retention/IDs, entity-warning collection and deduplication, logging-only graph timers and gesture-state reads. An inlinable empty release entry point erases calls and message evaluation. The debugging hardening below remains applicable to debug builds.

## Confirmed gaps and repairs

- **Release silence was incorrectly classified as a gap.** That behavior was intended; the correction above supersedes the release-persistence change.
- **Useful failures never reached SQLite.** REST failures became transient UI text, and WebSocket rejections, timeouts, overflow, and reconnect failures were absent at the app's warning threshold. Central failure boundaries now retain operation/request context, server response/error, and WebSocket connection/generation identifiers. Expected cancellation stays quiet.
- **Decoding and weather diagnostics discarded their original cause.** Typed WebSocket failure now records the full offending payload, type, and `DecodingError` before preserving the existing outward `invalidMessage` contract. Weather's once-per-attempt log retains entity/type and error detail. Lifecycle component transitions record new failures without changing state transitions. REST localized UI errors show the HTTP status/reason; full bodies remain in the error value and diagnostic rather than flooding the UI.
- **Embedded NUL truncated a selected message.** The writer used SQLite's negative-length C-string binding. It now supplies the explicit UTF-8 byte length and checks every bind result before executing/committing. The regression round-trips `before\0after 温度 🌡️`. This follows SQLite's [documented binding-length semantics](https://www.sqlite.org/c3ref/bind_blob.html).
- **New traffic bypassed failed-write retry pacing.** Threshold arrivals could immediately resubmit a retained failed batch. Retry state now gates those immediate writes, preserving order without discarding entries. Tests cover both the held retry boundary and automatic retry after releasing a lock.
- **Ordinary logger release lost a pending batch.** Scheduled callbacks hold weak references; deinitialization now attempts a final queue-safe flush. Concurrent-producer tests prove accepted rows are persisted exactly once.
- **Policy setup could race logging.** The public active-policy value is now lock-protected, and the app installs its policy during app initialization before constructing its scenes. Existing typed policy values are unchanged.
- **Inspection required ad hoc SQL.** `tools/read_logs.py` opens the database read-only, lists sessions by creation order, filters selected severity, category and text, and exports complete newline-delimited JSON. Its fixture test covers newest-session selection, result ordering/limit, Unicode/NUL fidelity, and rejecting an invalid table identifier.

No database rewrite, migration, retention deletion, graph behavior change, network retry change, or new settings surface is introduced. Protocol error, subscription delivery, cancellation, and generation semantics remain intact. The reader was also exercised against the existing local database's schema.
