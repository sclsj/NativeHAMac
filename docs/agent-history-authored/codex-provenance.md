The important correction is that a long, highly specific testing prompt was written by a Codex assistant and then pasted nearly verbatim by the user. ## Method

1. I preserved the first-pass report and treated its 49 normalized bullets as candidates to test, not as ground truth.
2. I searched both roles in the Codex corpus under `/Users/jin/.codex/sessions/**/*.jsonl`: direct user messages and assistant response text. I compared earlier assistant output to later user messages, including near-exact rather than only exact matching.
3. I decoded the Gemini conversation databases under `/Users/jin/.gemini/antigravity/conversations/*.db`. In the records examined, protobuf step type 14 held direct user text and step type 15 held model text. I searched both lineages.
4. For a structured or unusually polished user prompt, I looked backward for an AI-authored precursor. A later paste was not counted as user authorship unless the user supplied an identifiable new instruction. Small framing edits do not transfer authorship of the pasted body.
5. I used `USER_ORIGINATED` when the semantic instruction first appeared in direct user language and no earlier AI precursor was found; `AI_ORIGINATED` when the candidate's operative content first appeared in model output; `USER_DELTA_ON_AI` for an independently meaningful user addition to pasted/selected model text; `MIXED` when a candidate combined user and model contributions; and `UNRESOLVED` when the history supports the concern but not a standing user instruction or traceable AI precursor.
6. The `/Users/jin/Documents/HA...` side experiment remained excluded from *eligibility*. Its records could be consulted only to determine provenance—for example, to show that a terse instruction in the current workspace was consistent with earlier direct user language rather than generated by a model.
7. I did not promote task-specific bug reports, stale file/symbol/line references, implementation findings, or one-off fixture values. A direct user statement can still be ineligible as durable policy.

## Decisive copied-prompt lineage

At `2026-07-16T12:32:01.889Z` in C19, the user asked Codex to write a detailed future-session prompt that would add GUI and performance testing instructions to the module-plan documents. At `2026-07-16T12:40:25.303Z` in C20, the user pasted that prompt as an 18,379-character user message. After removing the assistant's wrapper, the bodies have a `difflib.SequenceMatcher` ratio of 0.9938136. The user's substantive additions were limited to:

- a parenthetical saying the prompt was just a reference and the agent could do its own code reading/research;
- the hass-frontend reference path, explicitly including `src` and `node_modules`;
- one additional newline.

The detailed testing clauses themselves were unchanged. Those clauses are therefore AI-authored even though they later occur in a user-role record. The user-authored high-level intent—add GUI/performance testing guidance to the plans—remains eligible, but the assistant's chosen mechanisms do not become user preferences merely through paste-back.

A second lineage affects the rescue/module plan. At `2026-07-15T08:26:10Z` in G-RESCUE, the direct Gemini user described NativeHA, asked whether it was rescueable, requested a comprehensive action plan grouped into modules small enough for one agent, and allowed connection to the live server to focus on currently used features. The original modularity/current-live-feature request is user-authored; plan-specific structure and prose are not.
